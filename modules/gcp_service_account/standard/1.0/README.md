# GCP Service Account — Standard

Creates a single **Google Cloud service account** in an explicit project, with
optional project-level role grants and optional impersonation (token-creator)
grants. Use it to provision least-privilege identities for workloads and CI —
for example a `facets-terraform` account that Terraform runners impersonate.

- **Clouds:** gcp
- **Resources created:** `google_service_account`,
  `google_project_iam_member` (per project role),
  `google_service_account_iam_member` (per token creator)
- **Output type:** `@facets/gcp_service_account`

---

## Architecture

```
   INPUTS                                RESOURCES (main.tf)                    OUTPUT
   ┌────────────────────────────┐        ┌──────────────────────────────────┐
   │ cloud_account              │        │ google_service_account "this"     │
   │  @facets/gcp_org_account   │─google─►│  account_id / display_name / desc │
   │  (google provider creds)   │provider │                                   │
   ├────────────────────────────┤        ├──────────────────────────────────┤  @facets/
   │ project                    │        │ google_project_iam_member         │─►gcp_service_
   │  @facets/gcp_project       │project─►│  member = serviceAccount:<email>  │  account
   │  .attributes.project_id    │  _id    │  one per spec.project_roles       │
   └────────────────────────────┘        ├──────────────────────────────────┤
                                         │ google_service_account_iam_member │
        spec.project_roles[]   ─────────►│  role = ...TokenCreator           │
        spec.token_creators[]  ─────────►│  one per spec.token_creators      │
                                         └──────────────────────────────────┘
```

`project_roles` grant the new SA roles **on its own project** (the SA is the
member). `token_creators` grant **other** members the right to impersonate
this SA (`roles/iam.serviceAccountTokenCreator` on the SA itself).

---

## Usage

```yaml
kind: gcp_service_account
flavor: standard
version: "1.0"
spec:
  account_id: facets-terraform          # immutable; changing it recreates the SA
  display_name: Facets Terraform
  description: Managed by Facets
  project_roles:
    - roles/container.admin
    - roles/cloudsql.admin
  token_creators:
    - serviceAccount:ci-sa@my-project.iam.gserviceaccount.com
```

`account_id` must match `^[a-z][a-z0-9-]{4,28}[a-z0-9]$`. Token creators are
fully-qualified IAM members (`serviceAccount:`, `group:`, `user:`).

---

## Inputs

| Input | Type | Required | Purpose |
|-------|------|----------|---------|
| `cloud_account` | `@facets/gcp_org_account` | Yes | Supplies the `google` provider credentials. |
| `project` | `@facets/gcp_project` | Yes | Project the SA is created in; `attributes.project_id`. |

## Spec

| Field | Required | Notes |
|-------|----------|-------|
| `account_id` | Yes | Immutable SA ID. Pattern `^[a-z][a-z0-9-]{4,28}[a-z0-9]$`. Changing it destroys and recreates the service account. |
| `display_name` | No | Human-readable name. Default `Facets Terraform`. |
| `description` | No | Description stored on the SA. Default `Managed by Facets`. |
| `project_roles` | No (default `[]`) | IAM roles granted to this SA **on its own project**. |
| `token_creators` | No (default `[]`) | Fully-qualified members allowed to impersonate this SA. |

---

## Outputs — `@facets/gcp_service_account`

No interfaces. Attributes:

| Attribute | Description |
|-----------|-------------|
| `service_account_email` | The SA email (e.g. `<account_id>@<project>.iam.gserviceaccount.com`). |
| `service_account_name` | Full resource name (`projects/.../serviceAccounts/...`). |
| `service_account_id` | The SA's `account_id`. |
| `unique_id` | GCP-assigned numeric unique ID. |
| `project_id` | Project the SA lives in. |

---

## Notes

- **`account_id` is immutable.** It feeds directly into `google_service_account.account_id`,
  which forces replacement on change. Pick it once.
- **Two grant directions, don't confuse them.** `project_roles` make the SA a
  *member* on its project (what the SA can do). `token_creators` make *other*
  members token-creators on this SA (who may impersonate it). Both use
  additive `*_iam_member` resources, so unrelated bindings are never touched.
- **Impersonation, not keys.** `token_creators` grants
  `roles/iam.serviceAccountTokenCreator`, the keyless impersonation path. No JSON
  key is generated by this module.
- **Idempotent keys.** Roles and token creators are keyed by their own value, so
  duplicates in a list collapse rather than erroring.
