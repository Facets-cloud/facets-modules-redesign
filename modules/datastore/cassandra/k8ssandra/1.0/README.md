# Cassandra (k8ssandra)

Runs real Apache Cassandra on Kubernetes via the
[k8ssandra-operator](https://github.com/k8ssandra/k8ssandra-operator)
(`K8ssandraCluster` CR, single datacenter `dc1`). Requires the
`k8ssandra-operator/helm` module (wired via `@facets/k8ssandra-operator`),
which is installed cluster-scoped.

## Why k8ssandra and not KubeBlocks

The KubeBlocks addon catalog (release-1.0 and main, verified 2026-08-17) has
**no cassandra addon**, so a `kubeblocks` flavor is not implementable. AWS
Keyspaces was rejected because it implements only a CQL subset — not full
Cassandra.

## Verified facts (do not change without re-verifying)

- Helm chart `k8ssandra-operator` `0.30.1` at `https://helm.k8ssandra.io/stable`
  (operator v1.32.x, bundles cass-operator).
- `serverVersion` support: Cassandra 3.11.X / 4.X.X / 5.X.X per the CRD.
- The version enum (3.11.17, 4.0.17, 4.1.10) lists only versions with a
  published `k8ssandra/cass-management-api` image on Docker Hub (checked
  2026-08-17). **5.0.x images are not published as plain x.y.z tags yet** —
  extend the enum only after verifying a tag exists.
- Superuser secret: `<cluster_name>-superuser` (keys `username`, `password`),
  generated by the operator when `superuserSecretRef` is unset.
- CQL contact service: `<cluster>-<dc>-service` on 9042, created by
  cass-operator.

## Interfaces

`default` (`@facets/cassandra`): `interfaces.cluster` with `endpoint`, `port`,
`username`, `password`, `connection_string` (`cassandra://…`), `endpoints`,
`secrets`. `attributes` (`@facets/cassandra_k8s`): `namespace`,
`cluster_name`, `datacenter`, `service_name`.

## Known limitations (v1.0)

- **No backup/restore**: k8ssandra's backup path is Medusa, which requires an
  object-storage bucket + credentials this module deliberately does not
  provision. Tracked in the Blackbuck backlog (CAS-2 follow-up).
- **No external access / LoadBalancer exposure**: in-cluster endpoint only.
  Adding an optional field later is non-breaking (RULE-023).
- Auth is always on (operator default); credentials are always generated,
  never user-supplied.
